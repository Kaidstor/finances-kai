# finances-kai — учёт финансов из терминала

CLI поверх того же HTTP-API, что у веб-приложения. Токен лежит в системном
хранилище ОС, профиль выбирается один раз — команды ниже работают без
дополнительной настройки.

## Быстрый старт

```bash
finances-kai ls                       # платежи за текущий месяц + сводка
finances-kai ls --period year --json  # то же машиночитаемо
finances-kai add -250 кофе --tag еда  # расход (минус), тег по имени
finances-kai new обед                 # платёж по шаблону
finances-kai doctor                   # профиль, токен, связь
```

**У любой читающей команды есть `--json`** — для разбора бери его, а не парси
таблицу: там цвета, неразрывные пробелы в разрядах и обрезанные id.

## Что важно знать до первой команды

- **Знак суммы задаёт направление**: `-250` — расход, `250` — доход. Это первый
  позиционный аргумент `add`, и он разбирается до флагов, поэтому `add -250 …`
  работает и минус не путается с флагом.
- **Теги и контрагенты — по имени, не по UUID.** Поиск без учёта регистра:
  сначала точное совпадение, потом подстрока. Неоднозначность — отказ со
  списком вариантов; тогда уточни запрос, а не подставляй id руками.
  Подтег находится по хвосту пути: `--tag кафе` → «Еда / кафе».
- **Период по умолчанию — текущий месяц.** Нужны все данные — `--period all`.
- **Звёздочка у суммы в выводе — платёж не оплачен** (`status: unpaid`).
- **Новый платёж по умолчанию неоплаченный** — как в веб-форме. Записываешь
  уже случившуюся трату — добавляй `--paid`.

## Платежи

```bash
finances-kai ls [фильтры]
finances-kai add <сумма> [описание] [--tag] [--cp] [--date] [--currency] [--paid]
finances-kai new <шаблон> [сумма] [--date] [--paid] [--description]
finances-kai show <id>
finances-kai edit <id> [--amount] [--date] [--description] [--paid|--unpaid] [--tag] [--cp]
finances-kai rm <id> [--yes]
```

`show`, `edit`, `rm` и `attach` принимают префикс id — тот, что печатает `ls`
в колонке ID.

`edit` меняет только переданные поля и печатает, что именно изменилось.
`--tag` и `--cp` **заменяют** набор целиком, а не добавляют к нему;
`--description ""` стирает описание. Ошибку распознавания правь через `edit`,
а не через удаление и повторное создание — у платежа могут быть вложения.

`--date` понимает `today`, `yesterday`, `tomorrow`, `сегодня`, `вчера`,
`завтра` и `YYYY-MM-DD`. По умолчанию сегодня.

`new` берёт из шаблона сумму, валюту, теги, контрагентов и статус; знак
проставляется по типу шаблона (`expense` → минус). Без `--description`
описанием станет описание шаблона, а если его нет — имя шаблона: пустым оно не
останется.

### Фильтры

```
--period today|week|month|year|all   month по умолчанию; week — с понедельника
--from YYYY-MM-DD --to YYYY-MM-DD    отменяют --period
--tag <имя>       --cp <имя>         повторяемые
--type income|expense
--status paid|unpaid                 только ls
--search <подстрока>                 только ls, по описанию
--limit N                            только ls, 0 — все
```

## Вложения: чеки и счета

```bash
finances-kai attach <id> ~/Downloads/чек.pdf     # приложить
finances-kai attach <id> скрин1.png скрин2.png   # несколько за раз
finances-kai attach <id> --list                  # что уже приложено
finances-kai attach <id> --rm <id-файла>         # убрать
```

Принимаются jpg, png, gif, webp, pdf, txt, csv, doc(x), xls(x) до 10 МБ.
Расширение и размер проверяются до отправки. Вложения попадают в архив `export`.

**Порядок при работе со скриншотом чека**: сначала создать платёж (`add`),
затем приложить к нему сам скрин (`attach`) — так в архиве со счетами будет
подтверждение траты.

## Аналитика

```bash
finances-kai stats [--period|--from|--to] [--income] [--limit N]
finances-kai forecast [--months N] [--by-subscription]
```

`stats` группирует расходы (или доходы с `--income`) по тегам в базовой валюте
пользователя. **Платёж с несколькими тегами учитывается в каждом целиком**,
поэтому сумма долей бывает больше 100% — это не ошибка: доля отвечает на
«сколько прошло через тег», а не «какая часть от целого». Не пересказывай доли
как доли бюджета.

`forecast` считает будущие списания по активным подпискам; горизонт 1..60
месяцев, по умолчанию 6.

## Справочники и экспорт

```bash
finances-kai tags                            # дерево тегов
finances-kai tags add "подписки" --color '#3b82f6'
finances-kai cp                              # контрагенты
finances-kai cp add "Азбука вкуса" --type organization --icon 🛒
finances-kai templates                       # шаблоны
finances-kai templates add "обед" --amount 450 --tag еда --paid
finances-kai templates add "премия" --type income
finances-kai templates rm обед [--yes]
finances-kai export --period year -o 2026.zip
```

В шаблоне сумма хранится **без знака**, направление задаёт `--type`
(`expense` по умолчанию). Минус в `--amount` снимается: иначе `new` добавил бы
знак повторно и расход стал бы доходом.

`export` отдаёт zip со счетами; без `-o` имя берётся от сервера и содержит
границы периода, `-o -` пишет в stdout. Если платежей за период нет, сервер
отвечает 404 — это не поломка CLI.

### Сохранённые наборы экспорта

Повторяющуюся выгрузку удобно держать набором: фильтры сохранены, период
задаётся при запуске.

```bash
finances-kai export --save аренда --type expense --tag аренда --cp Арендодатель
finances-kai export аренда --period year
finances-kai export --list
finances-kai export --forget аренда
```

Наборы локальные, лежат в конфиге CLI, в вебе их не видно. Теги и контрагенты
хранятся именами и разрешаются при запуске. Флаги запуска перекрывают
сохранённые; `--period` сбрасывает сохранённые `--from`/`--to`.

Просят «выгрузить как в прошлый раз» — сначала `export --list`, а не собирай
фильтры заново по памяти.

## Правила безопасности

- **Чтение — сразу**: `ls`, `show`, `stats`, `forecast`, `tags`, `cp`,
  `templates`, `attach --list`, `export`, `doctor` выполняй без вопросов.
- **`add`, `new`, `edit` пишут в боевые данные.** Сумму, дату и знак бери из
  слов пользователя, ничего не додумывая. Не уверен в сумме или направлении —
  спроси, а не угадывай: лишний платёж придётся искать и удалять руками.
- **Данные с картинки — всегда через подтверждение.** Распознавание чека
  ошибается в сумме, дате и валюте. Покажи, что вычитал, дождись «да» и только
  потом вызывай `add`. Пачку чеков не заводи одной командой без разбора —
  перечисли, что получилось, и спроси.
- **`rm` и `templates rm` — только с явного согласия пользователя** в текущей
  сессии. Без TTY команда требует `--yes`; **сам этот флаг не подставляй**,
  чтобы обойти подтверждение — покажи, что нашёл, и спроси.
- **Токен в аргументы не передавай.** `login` читает его со stdin или из
  `FINANCES_KAI_TOKEN`; в argv он был бы виден в `ps` и осел бы в истории шелла.
- Не печатай токен в чат. `doctor` и `profile` показывают только источник
  («системное хранилище», «файл»), самого значения там нет — так и надо.

## Профили и диагностика

```bash
finances-kai profile                                   # список, звёздочка — текущий
finances-kai profile add local http://localhost:3000
finances-kai login --profile local                     # токен профиля
finances-kai profile use local
finances-kai ls --profile prod                         # разово
finances-kai doctor [--profile <имя>]
```

Разовый запуск мимо профилей — через окружение:
`FINANCES_KAI_URL=… FINANCES_KAI_TOKEN=… finances-kai ls`.

**`doctor` — первое, что стоит запустить при любой непонятной ошибке**: он
показывает адрес, откуда взят токен, и проверяет связь одним запросом.

Расшифровка отказов:

- `не авторизован` — токен истёк или отозван. Новый выпускается в приложении
  (/settings → «API Токены»), затем `finances-kai login`. Повторять команду
  бессмысленно, сообщи пользователю.
- `нет токена для профиля` — профиль есть, токена к нему нет: `login --profile <имя>`.
- `сервер ответил …, а не JSON` — до приложения не дошли, отвечает прокси.
  Проверь адрес в `doctor` и что контейнер поднят.
- `тег … подходит к нескольким` — уточни имя, не подставляй id.

## Ограничения, о которых стоит помнить

- `GET /api/payments` отдаёт все платежи пользователя разом, и фильтры `ls`
  применяются уже в CLI. На больших объёмах это заметно; `export` фильтрует на
  сервере.
- Сводка внизу `ls` и весь `stats` считаются в базовой валюте пользователя
  (`amountInBaseCurrency`), а не в валюте каждого платежа.
- Подписок и правки их расписания в CLI нет — `forecast` только читает.
  Заводятся подписки в вебе.
