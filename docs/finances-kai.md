CLI к приложению учёта доходов и расходов
[finances](https://github.com/Kaidstor/finances-next). Ходит в тот же HTTP-API,
что веб-интерфейс и raycast-расширение, авторизуется API-токеном.

```
$ finances-kai ls --period month
ДАТА                СУММА  ОПИСАНИЕ       ТЕГИ      КОНТРАГЕНТЫ     ID
2026-07-15     -250,00 ₽   кофе           Еда       🛒 Азбука вкуса  11111111
2026-07-05  120 000,00 ₽   зарплата                                 33333333
2026-07-02   -1 200,50 ₽*  Netflix        Подписки  Netflix         22222222

2026-07-01 — 2026-07-31 · 3 записи
доход 120 000,00 ₽ · расход 1 450,50 ₽ · сальдо 118 549,50 ₽
```

Звёздочка у суммы — платёж не оплачен.

## Установка

```bash
brew install kaidstor/tap/finances-kai
```

Из исходников — [репозиторий](https://github.com/Kaidstor/finances-kai):

```bash
just install          # сборка в ~/.local/bin
just install-skill    # подключить скилл агенту
```

## Первый запуск

Токен выпускается в приложении: **/settings → «API Токены»**, живёт год.

```bash
finances-kai login --url https://paytracker.ru
finances-kai doctor
```

<div class="warn">
Токен читается со stdin или из <code>FINANCES_KAI_TOKEN</code> — аргументом его
передавать не нужно: в argv он виден любому процессу через <code>ps</code> и
оседает в истории шелла.
</div>

Хранится токен в системном хранилище — Keychain на macOS, libsecret на Linux.
Если хранилища нет, ложится файлом `~/.config/finances-kai/tokens/<профиль>` с
правами 0600, и `login` об этом предупредит. На macOS запись идёт через
`security -i` со stdin, чтобы токен не попал в argv и там.

## Команды

| | |
|---|---|
| `ls [фильтры]` | платежи за период |
| `add <сумма> [описание]` | создать платёж; минус — расход |
| `new <шаблон> [сумма]` | создать по шаблону |
| `show <id>` | карточка платежа |
| `edit <id> [поля]` | изменить платёж |
| `rm <id>` | удалить платёж |
| `attach <id> <файл>…` | приложить чеки и счета |
| `stats [фильтры]` | сводка по тегам |
| `forecast [--months N]` | прогноз по подпискам |
| `tags`, `tags add` | теги |
| `cp`, `cp add` | контрагенты |
| `templates`, `templates add/rm` | шаблоны |
| `export [набор] [фильтры]` | zip со счетами |
| `login`, `profile`, `doctor` | подключение |

У всех читающих команд есть `--json` — для разбора берите его, а не парсите
таблицу: там цвета, неразрывные пробелы в разрядах и обрезанные id.

## Платежи

```bash
finances-kai add -250 кофе --tag еда --paid
finances-kai add -1500 "подписка" --cp Netflix --currency USD --date yesterday
finances-kai add 120000 зарплата --date 2026-07-05 --paid
```

Знак задаёт направление: `-250` — расход, `250` — доход. Сумма идёт первым
позиционным аргументом.

`--date` понимает `today`, `yesterday`, `tomorrow`, `сегодня`, `вчера`,
`завтра` и `YYYY-MM-DD`; по умолчанию сегодня. Новый платёж по умолчанию
**неоплаченный** — как в веб-форме; `--paid` помечает оплаченным.

`show`, `edit`, `rm` и `attach` принимают префикс id — тот, что печатает `ls`
в колонке ID.

### Правка

```bash
finances-kai edit 11111111 --amount -300 --paid
finances-kai edit 11111111 --tag еда --tag кафе
finances-kai edit 11111111 --description ""
```

Меняются только переданные поля, после обновления печатается, что именно
изменилось. `--tag` и `--cp` **заменяют** набор целиком, а не добавляют к нему.
`--description ""` стирает описание.

## Теги и контрагенты — по именам

Смысл CLI поверх `curl` в том, что фильтры пишутся именами, а не
идентификаторами. Совпадение ищется без учёта регистра: **сначала точное,
потом по подстроке**. Порядок именно такой, иначе тег «Еда» было бы не выбрать
при наличии «Еда вне дома».

Подтег находится по хвосту пути: `--tag кафе` найдёт «Еда / кафе».

Если под запрос подходит несколько — команда откажет и перечислит варианты, а
не выберет наугад:

```
$ finances-kai ls --tag Е
ошибка: тег "Е" подходит к нескольким: Еда, Еда / кафе — уточните
```

## Фильтры

```
--period today|week|month|year|all   по умолчанию month
--from YYYY-MM-DD --to YYYY-MM-DD    отменяют --period
--tag <имя>                          повторяемый
--cp <имя>                           повторяемый
--type income|expense
--status paid|unpaid                 только ls
--search <подстрока>                 только ls, по описанию
--limit N                            ls и stats, 0 — без ограничения
```

`--period week` — текущая неделя с понедельника, `month` и `year` —
календарные.

<div class="note">
У <code>ls</code> отбор идёт на стороне CLI: в <code>GET /api/payments</code>
фильтров нет, сервер отдаёт все платежи разом. У <code>export</code> фильтрует
сервер.
</div>

## Экспорт и сохранённые наборы

```bash
finances-kai export --period year -o 2026.zip
finances-kai export --from 2026-01-01 --to 2026-06-30
finances-kai export --type expense --tag аренда
```

Повторяющуюся выгрузку удобно держать набором: фильтры сохранены, период
задаётся при запуске.

```bash
finances-kai export --save аренда --type expense --tag аренда --cp Арендодатель
finances-kai export аренда --period year
finances-kai export аренда --from 2026-01-01 --to 2026-06-30

finances-kai export --list
finances-kai export --forget аренда
```

Наборы локальные, лежат в `~/.config/finances-kai/config.json`, в веб-интерфейсе
их не видно. Теги и контрагенты хранятся **именами**: набор остаётся читаемым,
переживает пересоздание тега и работает в любом профиле, где есть такие же
имена. Переименовали тег — набор откажет вместо тихой выгрузки не тех данных.

Флаги в момент запуска перекрывают сохранённые. Отдельный случай: `--period`
сбрасывает сохранённые `--from`/`--to` — явные границы приоритетнее периода, и
без сброса переданный период молча не подействовал бы.

Имя файла приходит от сервера и содержит границы периода
(`invoices_01.01.2026-31.03.2026.zip`), поэтому выгрузки за разные периоды не
затирают друг друга.

## Вложения

```bash
finances-kai attach 11111111 ~/Downloads/чек.pdf
finances-kai attach 11111111 скрин1.png скрин2.png
finances-kai attach 11111111 --list
finances-kai attach 11111111 --rm <id-файла>
```

Принимаются jpg, png, gif, webp, pdf, txt, csv, doc(x), xls(x) до 10 МБ — тот
же список, что у веб-формы. Расширение и размер проверяются до отправки, все
файлы проверяются до первой загрузки: иначе часть уехала бы, команда упала бы
на середине, и пришлось бы выяснять, что успело загрузиться.

Вложения попадают в архив `export` вместе со счетами.

## Сводка и прогноз

```bash
finances-kai stats --period year
finances-kai stats --period month --income
finances-kai forecast --months 3
finances-kai forecast --by-subscription
```

```
$ finances-kai stats --period all
ТЕГ            СУММА  ДОЛЯ  ШТ
без тега  8 910,00 ₽   86%   1
Подписки  1 200,50 ₽   12%   1
Еда         250,00 ₽    2%   1

всё время · Расходы 10 360,50 ₽
```

<div class="warn">
Платёж с несколькими тегами попадает в каждый <b>целиком</b>, поэтому сумма
долей бывает больше 100%. Доля отвечает на «сколько прошло через тег», а не
«какая часть от целого» — делить сумму между тегами было бы враньём другого
рода.
</div>

Суммы в `stats` и в сводке под `ls` считаются в базовой валюте пользователя
(`amountInBaseCurrency`): платежи бывают в разных валютах, складывать их в
исходной нельзя.

## Шаблоны

```bash
finances-kai templates
finances-kai templates add "обед" --amount 450 --tag еда --paid
finances-kai templates add "премия" --type income
finances-kai templates rm обед
finances-kai new обед              # применить
finances-kai new аренда 45000      # с другой суммой
finances-kai new обед --description "бизнес-ланч у офиса"
```

В шаблоне сумма хранится **без знака**, направление задаёт `--type` (`expense`
по умолчанию). Минус в `--amount` снимается: иначе `new` добавил бы знак
повторно и расход стал бы доходом.

Описание платежа `new` берёт из шаблона, а если в шаблоне его нет — подставляет
имя шаблона. `--description` перебивает и то и другое; `--description ""`
создаёт платёж без описания.

## Профили

```bash
finances-kai profile                                   # список
finances-kai profile add local http://localhost:3000
finances-kai login --profile local
finances-kai profile use local
finances-kai ls --profile prod                         # разово
```

## Переменные окружения

| | |
|---|---|
| `FINANCES_KAI_URL` | адрес приложения; работает без сохранённого профиля |
| `FINANCES_KAI_TOKEN` | токен вместо хранилища |
| `FINANCES_KAI_PROFILE` | профиль вместо текущего |
| `FINANCES_KAI_HOME` | каталог конфигурации |
| `NO_COLOR` | отключить цвет |

Цвет выключается и сам, когда вывод уходит в пайп или файл.

## Если что-то не так

`finances-kai doctor` — первое, что стоит запустить: показывает адрес, откуда
взят токен, и проверяет связь одним запросом.

| Сообщение | Что делать |
|---|---|
| `не авторизован` | токен истёк или отозван — выпустить новый в /settings и `login` |
| `нет токена для профиля` | `login --profile <имя>` |
| `сервер ответил …, а не JSON` | отвечает прокси, а не приложение — проверить адрес и контейнер |
| `тег … подходит к нескольким` | уточнить имя, не подставлять id |

## Как устроено внутри

Go, из зависимостей только стандартная библиотека. Тонкий `main.go`, всё
остальное в `internal/`: `command` (роутер на `switch` и команды), `api`
(HTTP-клиент), `config` (профили и наборы), `keyring` (токены), `output`
(таблицы, цвета, форматирование).

Две вещи, на которых это ловилось при разработке и которые стоит помнить, если
будете править:

**Пакет `flag` прекращает разбор на первом позиционном аргументе.** Поэтому
`add -250 "кофе" --tag еда --paid` без предобработки терял `--tag` и `--paid`, а
описанием становилась строка с ними. Позиционные аргументы отделяются от флагов
до `Parse`. Та же ловушка срабатывала в `rm <id> --yes` и `cp add <имя> --icon`.

**`multipart.CreateFormFile` ставит частям `application/octet-stream`**, а
сервер сверяет тип с белым списком и такой запрос отвергает. Тип проставляется
по расширению; таблица соответствий продублирована из
`lib/services/file-storage.ts` приложения и закрыта тестом на расхождение.

Ширина колонок считается в знакоместах, а не в рунах: escape-коды цвета
невидимы, эмодзи и CJK занимают два — иначе колонка с иконкой контрагента
разъезжается.
